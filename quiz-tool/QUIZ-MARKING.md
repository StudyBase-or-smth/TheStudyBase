# Quiz marking with Jev

The tool entry point is `quiz-tool/quiz-tool.html`. Keep the legacy progress storage key so the rename preserves saved quiz sessions. Existing Continue studying entries resolve to the renamed page.

Written questions (`isAICheck: true`) use the authenticated backend endpoint
`POST /api/quizGrade`. There is no Gemini call, direct-browser provider call,
generated feedback, or fallback provider in the quiz tool. Multiple choice and
mathematical answer checks continue to use the existing local checks.

Configure `TYPESAFE_API_KEY` on the backend and deploy both repositories together.
`TYPESAFE_MODEL` is optional; it defaults to the pinned `jev-1.13.0` model.
Never put the TypeSafe key in quiz JSON or frontend configuration.

## Authoring fields

`answer` remains the private-to-the-marking-flow reference guidance. Provide
`markingLevels` to describe every whole-number band from zero through `marks`.
All current written questions have explicit bands. Legacy questions without
bands can still use their existing guidance with generic credit-band options;
explicit descriptions are preferred, especially for partial credit.

`completionGuide` is an **optional prewritten string** explaining how to complete
the task. It is shown below the mark after submitting, including on reopening a
completed question. It can be used on locally marked questions too. It is plain
text, supports line breaks, and is never sent to Jev or generated by the model.
When absent or empty, no guidance section appears. Old saved generated feedback
is no longer displayed for written questions.

```json
{
  "id": "example",
  "question": "Identify an effect and suggest a risk-reduction strategy.",
  "isAICheck": true,
  "marks": 2,
  "answer": "Credit one valid effect and one valid strategy. Accept equivalent wording.",
  "markingLevels": {
    "0": "Neither part is correct.",
    "1": "Only one part is correctly addressed.",
    "2": "Both a valid effect and a valid strategy are identified."
  },
  "completionGuide": "Identify a clear effect, then explain a practical way to reduce that risk. Address both parts."
}
```

The server asks a TypeSafe Choice question with a fixed option for each mark
band and returns only `earned`, `total`, `provider`, `model`, and `confidence`.
The UI displays the mark and any author-written guide. Invalid provider results
and request failures leave the answer editable for retry, rather than recording
a zero mark. A completed question retains its original mark when reopened.

References: [TypeSafe HTTP API](https://docs.typesafe.ai/api),
[Choice](https://docs.typesafe.ai/primitives/choice),
[model versions](https://docs.typesafe.ai/models).
Mocked integration tests verify the contract; live grading quality requires
comparison against teacher-marked responses using a configured TypeSafe account.
